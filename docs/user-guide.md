# 用户手册（T16）

面向**使用者**（不涉及开发细节）。开发与架构说明见 `docs/architecture.md`。

---

## 1. 安装

### 方式一：免安装（推荐）

1. 下载 `p2pdl-<版本>-win-x64.zip`
2. 解压到任意目录（例如 `D:\Tools\p2pdl`）
3. 双击 `p2pdl-gui.exe`

> 建议先核对校验和：`p2pdl-<版本>-win-x64.zip.sha256` 中给出了 SHA-256。
> 在 PowerShell 中执行 `(Get-FileHash .\p2pdl-1.0.0-win-x64.zip -Algorithm SHA256).Hash` 比对。

### 方式二：脚本安装

解压后在该目录执行：

```powershell
.\install.ps1
```

会复制到 `%LOCALAPPDATA%\Programs\p2pdl` 并创建开始菜单快捷方式（**无需管理员权限**）。
卸载：运行安装目录下的 `uninstall.ps1`。

### 系统要求

- Windows 10 1809 及以上（x64）
- **Microsoft Edge WebView2 Runtime**：Windows 11 与较新的 Windows 10 已内置。
  若缺失，启动时会弹窗说明并提供官方下载页；安装后重新运行即可。

## 2. 快速上手

### 下载一个 HTTP 链接

1. 打开 `p2pdl-gui.exe`
2. 在输入框粘贴链接（支持 `http://` / `https://`）
3. 点「开始下载」

### 下载磁力链或种子

- **磁力链**：粘贴 `magnet:?xt=urn:btih:...` 后点「开始下载」
- **种子文件**：把 `.torrent` 文件**直接拖进窗口**，或填入其本地路径

### 带完整性校验下载（推荐）

若你能拿到文件的官方摘要（例如 `sha256sum` 输出），把它粘到第二个输入框，
下载完成后会自动校验；**校验失败时，若此前生成过分块清单，只会重下受损的少量数据块**。

**状态灯**：

| 颜色 | 含义 |
|---|---|
| 绿 | 引擎运行中，括号内是控制面地址 |
| 红 | 引擎未运行，右侧文字给出原因（如「引擎进程已退出」）→ 点「重启引擎」 |

**任务状态**：等待中 / 下载中 / 已暂停 / 校验中 / 已完成 / 失败。

**可用操作**（按状态显示不同按钮）：

| 按钮 | 说明 |
|---|---|
| 暂停 | 停止传输但保留已下载数据 |
| 继续 | 从断点继续（不会重下已完成部分） |
| 校验 | 重新校验；若之前生成过分块清单，只重下受损块 |
| 打开 | 在资源管理器中定位文件 |
| 删除 | 删除任务记录，**保留已下载的文件** |

**其他**：

- 「读剪贴板」：从剪贴板填入链接（窗口获得焦点时会自动识别一次，不打断你正在输入的内容）
- 底部「运行日志」：排障用，包含引擎输出
- 关闭窗口时若仍有任务：会询问「保留后台下载 / 停止并退出 / 取消」

## 4. 命令行用法

`dl.exe` 与 GUI 共享同一个引擎与配置。

```powershell
# 启动引擎（前台，不打开界面）
.\dl.exe serve --data-dir D:\downloads

# 新建任务并实时看进度
.\dl.exe add "https://example.com/big.iso" --name big.iso

# 带校验下载
.\dl.exe add "https://example.com/big.iso" --hash "9f86d081884c7d65..."

# 磁力链 / 种子
.\dl.exe add "magnet:?xt=urn:btih:..." --timeout 30m
.\dl.exe add --torrent .\release.torrent --peers 10.0.0.5:6881

# 任务管理
.\dl.exe list
.\dl.exe pause <任务ID>
.\dl.exe resume <任务ID>
.\dl.exe recheck <任务ID>
.\dl.exe rm <任务ID> --files

# 状态与限速
.\dl.exe status
.\dl.exe limit 2MB        # 全局限速 2 MB/s
.\dl.exe limit 0          # 关闭限速

# 自动监视全部任务
.\dl.exe watch
```

所有命令都支持 `--json` 便于脚本处理。

**退出码**：`0` 成功、`1` 运行期错误、`2` 用法错误。

详见 `docs/cli.md`。

## 5. 设置

界面右上角「设置」。设置保存在 `%APPDATA%\p2pdl\settings.json`。

### 启动期设置（修改后需重启引擎才生效）

| 项 | 默认 | 说明 |
|---|---|---|
| 下载目录 | `%USERPROFILE%\Downloads\p2pdl` | 文件保存位置 |
| 单任务并发连接数 | 8 | 越大越快，但占用更多带宽与内存；1~64 |
| 同时运行任务数 | 3 | 1~32 |
| 分块大小 | 1 MB | 断点记录粒度；越大元数据越小、重下粒度越粗 |
| 控制面端口 | 0（自动） | 固定端口便于排查 |

### 运行期设置（保存即生效）

| 项 | 说明 |
|---|---|
| 全局限速 | 0 表示不限速。也可用界面上的下拉框快速切换 |

### 行为开关

| 项 | 默认 | 说明 |
|---|---|---|
| 启动时自动继续未完成的任务 | 开 | 关闭后，中断的任务以「暂停」状态恢复，等你手动继续 |
| 校验通过后生成分块清单 | 关 | 开启后完成时会多读一遍文件生成清单，但**之后校验能精确定位损坏块，只重下少量数据** |
| 任务完成/失败时提醒 | 开 | |
| 自动识别剪贴板中的链接 | 开 | 仅在窗口聚焦时读取 |

## 6. 数据与备份

| 内容 | 位置 |
|---|---|
| 下载的文件 | `<下载目录>` |
| 未完成的临时文件 | `<下载目录>\.<文件名>.p2pdl.part` |
| 分块清单 | `<文件名>.p2pdl.manifest` |
| 任务元数据（断点/位图/索引） | `<下载目录>\.p2pdl\` |
| 用户设置 | `%APPDATA%\p2pdl\settings.json` |

**迁移到新机器**：复制「下载目录」整个文件夹（含 `.p2pdl`）即可，
任务与断点会被完整恢复；`settings.json` 可选。

**损坏元数据**：若某个任务的元数据损坏，引擎会把它移到 `<下载目录>\.p2pdl\corrupt\`
并跳过，其余任务不受影响。该任务需要重新添加。

## 7. 常见问题

**Q：下载一直没开始？**
1. 展开底部「运行日志」看具体原因；
2. 检查磁盘剩余空间——开始前会做预检查，不足时会直接报错而不是下到一半才失败；
3. 若是 BT 任务且没有进度，可能是网络出口阻断了 BT 流量或 DHT 域名被污染
   （见 `docs/e2e-report.md` 标准 4 的说明），此时可尝试提供静态 peer（`--peers`）。

**Q：关掉窗口下载会停止吗？**
默认会停止（并清理引擎进程）。关闭时确认框中选择「保留后台下载」则会继续，
之后再次打开界面即可接管。

**Q：速度比预期慢？**
- 单个源站带宽有限：多段并发（提高「单任务并发连接数」）通常有帮助；
- 源站不支持 Range 时会自动降级为单流模式，速度上限就是单连接速度——日志里会写明；
- 检查是否设置了全局限速。

**Q：下载完成但文件打不开 / 校验失败？**
在任务上点「校验」。若之前开启过「生成分块清单」，只会重下受损的少量数据块；
否则需要重新下载。反复失败通常是磁盘问题或网络持续损坏，任务会在 3 次修复后停止并给出原因。

**Q：任务显示「失败」，怎么重试？**
点「继续」即可重新排队；已下载的部分不会丢。

**Q：能同时开两个界面吗？**
可以。第二个界面会通过网络端点发现并**复用**已在运行的引擎，不会启动第二个引擎进程。
（不要手动同时运行两个引擎指向同一数据目录——BT 的 piece completion 数据库是独占锁。）

**Q：杀毒软件报警？**
Go 编写的下载器（尤其带 BitTorrent 客户端）可能被启发式误判。
建议核对本文档 §1 的 SHA-256；若确认误报，可向杀软厂商提交申诉。
本项目未对二进制做代码签名。

**Q：支持 macOS / Linux 吗？**
引擎与 CLI 的代码是跨平台的（`internal/engine` 无平台依赖），
但桌面壳目前只提供 Windows 打包，且未在其他平台验证。

## 8. 卸载

```powershell
# 脚本安装的：运行安装目录下的卸载脚本
.\uninstall.ps1

# 免安装的：直接删除解压出来的文件夹
```

**注意**：卸载不会删除你下载的文件，也不会删除 `%APPDATA%\p2pdl` 设置
（以免误删个人配置）。需要彻底清理时手动删除这两处。
